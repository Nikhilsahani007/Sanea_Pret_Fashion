# Sanéa Pret — Database Design

Status: Approved baseline (D-028), aligned with D-029 to D-034 and D-051 to D-059 · Date: 2026-10-19 · Database: PostgreSQL 18 via Prisma 7.10.1

Phase 6 builds only the tables listed for it in §6; the rest arrive in the phases named there. The schema file is `prisma/schema.prisma`. No migration has been run; the first one needs your approval before it is applied.

## 1. Conventions

- Primary keys: UUID v7 (`id`), generated by PostgreSQL 18's `uuidv7()` as the column default (D-051), so inserts from raw SQL, tests and seeds also get v7 IDs.
- Names: models and fields are PascalCase and camelCase in Prisma; tables and columns are snake_case in the database through `@@map` and `@map` (D-056).
- Timestamps: `createdAt`, `updatedAt` in UTC (`timestamptz(3)`).
- Money: integer paise in `Int` columns named `…Paise`. A ₹1,29,999 kurta is `12999900`. `Int` (max ≈ ₹2.1 crore per value) is enough for single prices and order totals.
- Soft delete is avoided for orders and stock (they are never deleted). Catalogue items use `status = ARCHIVED`.
- Enums are PostgreSQL enums generated by Prisma.
- Extensions: `citext` (case-insensitive email) from Phase 6; `pg_trgm` arrives with search in Phase 8 (D-081).
- Handwritten SQL: extensions, CHECK constraints and triggers are written into the migration files. Prisma does not model them, and its drift check does not notice if one is removed (Phase 6 compatibility test), so integration tests assert that each exists and works.
- Trigger errors use the default SQLSTATE `P0001`. A code such as `23001` makes Prisma report a misleading foreign-key error (P2003).

Search fields are added in Phase 8 with the search module (D-054). A search vector across category, collection and colour names cannot be a generated column, because generated columns cannot read other tables.

**Phase 8 search design (D-081 as amended by Q8-1; migration `20261021180245_catalogue_search` written and validated on disposable databases, awaiting approval; `phase-8-plan.md` §10d):**
- **Column:** `product.search_vector`, type `tsvector`, `NOT NULL DEFAULT ''`. In Prisma it is `Unsupported("tsvector")`, so it is read and written only through reviewed raw SQL.
- **Text-search configuration:** `simple`, so transliterated garment names such as "Anarkali" are not stemmed as English.
- **Weights:**
  - A: product name;
  - B: category name, collection names and the names of the colours of the product's **active** variants (an inactive variant's colour is not searchable);
  - C: short description and the text of the description: the string values under the key `text`, where canonical rich-text text nodes store their words (R2, 2026-10-22). Other JSON is ignored, never an error.
- **Maintenance:** handwritten trigger functions recompute the vector whenever any of these change:
  - the product's own fields;
  - a category name (all products in that category);
  - a collection name (all products in that collection);
  - a collection's membership (`collection_product` insert and delete);
  - a variant's colour or active flag (`product_variant` insert, update of product, colour or `is_active`, and delete);
  - a colour name (all products with a variant in that colour).

  The migration backfills existing rows. Like the other handwritten objects, the functions and triggers are listed in `apps/api/src/db/handwritten.ts` and checked against the migration SQL and the live catalogue.
- **Trigger tests:** these are required (Phase 8 safeguard 3). They cover product updates and renames of a shared category, collection or colour that must update every affected product, and none other.

### 3.3 Customers and carts

Customer, Address and WishlistItem are **deferred to a later release (D-034).** Release one keeps only Cart and CartItem, with no customer link (Phase 11 adds none; accounts add it when scheduled); `Order.customerId` stays nullable so accounts can be added later without reworking orders.

**Customer**: id, email (citext, unique), phone (E.164, `+91…`), firstName, lastName, passwordHash?, emailVerifiedAt?, marketingConsent (bool, with consentAt), codBlocked (bool), createdAt.

**Address**: id, customerId, fullName, phone, line1, line2?, landmark?, city, state (enum of Indian states and UTs), pinCode (char(6), `CHECK ~ '^[1-9][0-9]{5}$'`), isDefault.

**WishlistItem**: customerId + productId (composite PK), createdAt.

**Cart**: id, tokenHash (bytea, exactly 32 bytes, unique; the raw token is only in the cookie), createdAt, updatedAt, expiresAt (after createdAt). No customerId in release one (D-034).

**CartItem**: cartId + variantId (composite PK), quantity (`CHECK 1..10`).

### 3.5 Content, enquiries, media

**ContentBlock**: id, key (unique, e.g. `home.hero`), type (enum from `system-design.md` §7), draft (jsonb), published (jsonb?), publishedAt?, publishedByAdminId?.

**Page**: id, slug (unique), title, body draft/published (jsonb), seoTitle, seoDescription, status, requiresVerification (bool; true for `rehma-foundation`), verifiedByAdminId?, verifiedAt?. `CHECK NOT requiresVerification OR status <> 'PUBLISHED' OR verifiedAt IS NOT NULL`: the database refuses to publish unverified Rehma Foundation content.

**NavigationItem**: id, menu (`HEADER`, `CATEGORY_PILLS`, `FOOTER_*`), label, targetType, targetId or url, position.

**StoreSetting**: key (PK), value (jsonb), updatedAt, updatedByAdminId. Holds WhatsApp number, contact details, COD rules, shipping rules.

Enquiry and WhatsAppClick arrive in Phase 13 (D-054).

**Enquiry**: id, source (`WEBSITE`), productId?, variantId?, name, email?, phone?, message, consentToContact (bool, required true), status (`NEW/IN_PROGRESS/CLOSED`), assignedAdminId?, ipHash, createdAt.

**WhatsAppClick**: id, productId?, variantId?, pagePath, sessionId (anonymous), createdAt.

**MediaAsset**: id, storageKey, originalFilename, mimeType, width, height, bytes, variants (jsonb of derived sizes), uploadedByAdminId, createdAt.

### 3.6 Admin and security

**AdminUser**: id, email (citext, unique), name, passwordHash, role (enum `OWNER/MANAGER/CATALOGUE_EDITOR/FULFILMENT`, the same values as `AdminRole` in `@sanea/shared`), mfaSecret? (encrypted; 2FA is mandatory for all four roles, D-032, enforced in Phase 7), isActive, lastLoginAt, failedLoginCount, lockedUntil?.

**AdminSession**: id, adminUserId (FK AdminUser, `ON DELETE CASCADE`), tokenHash (unique; SHA-256 of the cookie token, never the token), createdAt, lastSeenAt, expiresAt, ipHash, userAgent (D-055). Customer sessions return with customer accounts (D-034).

Staff invites, password-reset tokens and MFA recovery codes are designed with admin authentication in Phase 7 (D-054).

**AuditLog** (append-only: a trigger rejects UPDATE, DELETE and TRUNCATE, D-057; `actorAdminId` uses `ON DELETE RESTRICT`, so admins are deactivated, not deleted): id, actorAdminId, action (e.g. `product.update`), entityType, entityId, before (jsonb?), after (jsonb?), ipHash, createdAt.
