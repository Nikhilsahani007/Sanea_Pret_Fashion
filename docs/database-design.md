# Sanéa Pret — Database Design

Status: Draft for approval · Date: 2026-10-18 · Database: PostgreSQL 16 via Prisma

No schema file or migration exists yet. This is the initial logical model for review.

## 1. Conventions

- Primary keys: UUID v7 (`id`).
- Timestamps: `createdAt`, `updatedAt` in UTC (`timestamptz`).
- Money: integer paise in `Int` columns named `…Paise`. A ₹1,29,999 kurta is `12999900`. `Int` (max ≈ ₹2.1 crore per value) is enough for single prices and order totals.
- Soft delete is avoided for orders and stock (they are never deleted). Catalogue items use `status = ARCHIVED`.
- Enums are PostgreSQL enums generated by Prisma.
- Extensions: `pg_trgm` (search), `citext` (case-insensitive email).

## 2. Entity overview

```
Category 1──* Product *──* Collection        (via CollectionProduct, with position)
Product  1──* ProductVariant *──1 Colour
                       │      *──1 Size
                       └──1 InventoryLevel 1──* StockMovement
                       └──* StockReservation
Product  1──* ProductImage *──0..1 Colour

Customer 1──* Address
Customer 1──* WishlistItem *──1 Product
Customer 0..1──* Cart 1──* CartItem *──1 ProductVariant

Order 1──* OrderItem *──1 ProductVariant      (with price/name snapshot)
Order 1──* OrderStatusEvent
Order 1──* Payment 1──* PaymentEvent
Payment 1──* Refund
Order 1──* Shipment
Order *──0..1 Customer                        (guest orders have none)

Enquiry *──0..1 Product / ProductVariant
WhatsAppClick *──0..1 Product / ProductVariant

AdminUser 1──* Session   Customer 1──* Session
AdminUser 1──* AuditLog
ContentBlock, Page, NavigationItem, StoreSetting, MediaAsset
```

### 3.3 Customers and carts

**Customer**: id, email (citext, unique), phone (E.164, `+91…`), firstName, lastName, passwordHash?, emailVerifiedAt?, marketingConsent (bool, with consentAt), codBlocked (bool), createdAt.

**Address**: id, customerId, fullName, phone, line1, line2?, landmark?, city, state (enum of Indian states and UTs), pinCode (char(6), `CHECK ~ '^[1-9][0-9]{5}$'`), isDefault.

**WishlistItem**: customerId + productId (composite PK), createdAt.

**Cart**: id, tokenHash (unique; the raw token is only in the cookie), customerId?, updatedAt, expiresAt.

**CartItem**: cartId + variantId (composite PK), quantity (`CHECK 1..10`).

### 3.4 Orders and payments

**Order**
| Column | Type | Notes |
|--------|------|-------|
| id | uuid | PK |
| orderNumber | text | unique, e.g. `SP-2611-000123` |
| customerId | uuid? | null for guest |
| email, phone | text | snapshot |
| shippingAddress, billingAddress | jsonb | snapshot, validated by shared schema |
| status | enum (see `system-design.md` §5) | |

| idempotencyKey | text | unique per customer/cart |
| notes | text? | internal |
| placedAt, confirmedAt, cancelledAt | timestamptz? | |

**OrderItem**: id, orderId, variantId, productName, variantLabel ("Ivory / M"), sku, unitPricePaise, quantity, lineTotalPaise, gstRateBps?, hsnCode?. Snapshots keep the order correct even if the product changes later.

**OrderStatusEvent**: id, orderId, fromStatus?, toStatus, actorType (`SYSTEM/ADMIN/CUSTOMER/PROVIDER`), actorId?, note?, createdAt.

**Shipment**: id, orderId, courierName, trackingNumber, trackingUrl?, shippedAt, deliveredAt?.

**Payment**
| Column | Type | Notes |
|--------|------|-------|
| id | uuid | PK |
| orderId | uuid | FK |
| method | enum `PREPAID/COD` | |
| provider | text | `mock`, later `razorpay` etc. |
| providerPaymentId | text? | unique with provider |
| status | enum (see `system-design.md` §6.2) | |
| amountPaise | int | |

**PaymentEvent**: id, paymentId?, provider, providerEventId (unique with provider), type, rawPayload (jsonb), receivedAt, processedAt?.

**Refund**: id, paymentId, amountPaise, reason, status, providerRefundId?, createdByAdminId, createdAt.

### 3.5 Content, enquiries, media

**ContentBlock**: id, key (unique, e.g. `home.hero`), type (enum from `system-design.md` §7), draft (jsonb), published (jsonb?), publishedAt?, publishedByAdminId?.

**Page**: id, slug (unique), title, body draft/published (jsonb), seoTitle, seoDescription, status, requiresVerification (bool; true for `rehma-foundation`), verifiedByAdminId?, verifiedAt?.

**NavigationItem**: id, menu (`HEADER`, `CATEGORY_PILLS`, `FOOTER_*`), label, targetType, targetId or url, position.

**StoreSetting**: key (PK), value (jsonb), updatedAt, updatedByAdminId. Holds WhatsApp number, contact details, COD rules, shipping rules.

**Enquiry**: id, source (`WEBSITE`), productId?, variantId?, name, email?, phone?, message, consentToContact (bool, required true), status (`NEW/IN_PROGRESS/CLOSED`), assignedAdminId?, ipHash, createdAt.

**WhatsAppClick**: id, productId?, variantId?, pagePath, sessionId (anonymous), createdAt.

**MediaAsset**: id, storageKey, originalFilename, mimeType, width, height, bytes, variants (jsonb of derived sizes), uploadedByAdminId, createdAt.

### 3.6 Admin and security

**AdminUser**: id, email (citext, unique), name, passwordHash, role (enum `OWNER/MANAGER/CATALOGUE_EDITOR/FULFILMENT`), mfaSecret? (encrypted), isActive, lastLoginAt, failedLoginCount, lockedUntil?.

**Session**: id, tokenHash (unique), subjectType (`ADMIN/CUSTOMER`), subjectId, createdAt, lastSeenAt, expiresAt, ipHash, userAgent.

**PasswordResetToken**: id, subjectType, subjectId, tokenHash, expiresAt, usedAt?.

**AuditLog** (append-only): id, actorAdminId, action (e.g. `product.update`), entityType, entityId, before (jsonb?), after (jsonb?), ipHash, createdAt.

## 4. Key indexes

| Table | Index | Purpose |
|-------|-------|---------|
| Product | GIN(searchVector), GIN trigram(name) | search |
| Product | (status, publishedAt DESC) | New Ins |
| ProductVariant | (productId), unique(sku) | |
| InventoryLevel | expression index on `(onHand - reserved - lowStockThreshold)`, read through a `LowStockVariant` view | low-stock list |
| StockReservation | (status, expiresAt) | expiry job |
| Order | (status, placedAt DESC), (customerId), unique(orderNumber) | admin lists |
| PaymentEvent | unique(provider, providerEventId) | webhook dedupe |
| Enquiry | (status, createdAt DESC) | inbox |

## 5. Data retention

| Data | Retention (default, pending legal review OD-12) |
|------|---------------------------------------------|
| Orders, payments, invoices | 8 years (Indian accounting and GST record-keeping) |
| Carts | 30 days after last activity |
| Sessions | until expiry plus 30 days |
| Enquiries | 2 years, then anonymised |
| WhatsApp click logs | 12 months |
| Audit log | 3 years |
